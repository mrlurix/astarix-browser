Security FAQ & Troubleshooting

Security Model

Hardened in two directions: the web can't reach you, and tampering can't reach the app.

Protecting you from the web

The UI runs sandboxed with context isolation, no Node integration, and a strict Content Security Policy.
  • Non-http(s) navigation, redirects and popups are blocked
  • webview sources are restricted to http(s); attached guests get preloads stripped and locked-down preferences
  • All rendered text (titles, URLs, suggestions, history) is HTML-escaped; stored data is schema-validated on load

Protecting the app

LayerWhat it does
ObfuscationProduction JS is obfuscated (control-flow flattening, string encryption)
Electron FusesRunAsNode off, Node-options/CLI-inspect disabled, asar integrity on, load-from-asar only
Switch blockingRemote-debugging, insecure-content and isolation-disabling flags exit the app at startup
In-app DevTools (F12) stay available to you. Only remote attachment from other processes is blocked.

Extension screening

Manifests are inspected before an extension loads. Blocked:

  • Dangerous permissions: nativeMessaging, webRequestBlocking, proxy, debugger, management, browsingData, privacy, cookies, downloads, declarativeNetRequest*
  • Broad host access: <all_urls> and *://*/* in permissions or content-script matches

Downloads

  • Every download opens a Save dialog — silent drive-by downloads are impossible
  • Filenames are sanitized: no path traversal, no control characters, no reserved Windows names
